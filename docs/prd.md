# PRD: PDF 요약 웹 앱

- 문서 상태: 초안 v0.1 (2026-11-26)
- 작성: 프로덕트 매니저
- 표기 규칙: "사용자 결정"은 사용자가 직접 정한 내용, "추천안"은 PM이 제안했고 확인이 필요한 내용, "열린 질문"은 아직 정해지지 않은 내용이다. 기술 선택(프레임워크, AI 모델, 배포 방식, 저장 여부)은 다음 설계 단계에서 정한다.

## 1. 배경과 문제 정의

대학생은 강의 자료와 논문 PDF를 많이 읽어야 한다. 분량이 길고, 논문은 외국어(주로 영어)로 되어 있어 핵심을 파악하는 데 시간이 오래 걸린다. 시험 공부와 과제 준비 시점에는 "이 문서가 무슨 내용이고, 꼭 알아야 할 정의와 용어가 무엇인가"를 빨리 알고 싶다.

문제는 다음과 같다.

- 긴 문서를 처음부터 끝까지 읽기 전에는 핵심을 알기 어렵다.
- 영어 논문은 내용 파악 전에 번역과 이해 부담이 먼저 온다.
- 시험·과제에 필요한 정의, 용어, 공식을 문서 곳곳에서 직접 찾아 모아야 한다.

해결 방향: PDF를 올리면 AI가 한국어로 한 줄 요약, 핵심 내용, 중요한 정의·용어·공식을 정리해 보여 주는 웹 앱을 만든다.

## 2. 목표와 성공 기준

### 2.1 목표

1. 대학생이 PDF 한 개를 올리고 한국어 요약을 바로 볼 수 있다.
2. 요약 결과를 시험 공부·과제 준비에 쓸 수 있도록 복사해서 옮길 수 있다.
3. 요약이 실패하는 경우 사용자가 이유를 알고 다음 행동을 할 수 있다.

### 2.2 성공 기준 (측정 가능)

| # | 성공 기준 | 측정 방법 |
|---|-----------|-----------|
| S1 | 글자가 있는 4MB 이하 PDF를 올리면 요약 화면에 한 줄 요약, 핵심 내용, 정의·용어·공식이 모두 표시된다(문서에 공식이 없으면 공식은 생략) | 대표 시험용 PDF 모음(강의 자료·논문, 한국어·영어 포함)으로 수동 시험, 전부 통과 |
| S2 | PDF가 아닌 파일, 4MB 초과 파일, 글자가 없는 PDF를 올리면 각각 이유를 알려 주는 오류 안내가 표시된다 | 오류 상황별 시험(7절 목록)으로 확인, 전부 통과 |
| S3 | 배포 주소(공개 URL)에서 S1, S2가 동일하게 동작한다 | 배포 주소에서 같은 시험 반복 |
| S4 | 원문이 영어 등 외국어여도 요약 언어는 항상 한국어다 | 영어 PDF 시험에서 요약 본문이 한국어인지 확인 |
| S5 | 요약 복사 단추를 누르면 화면에 보이는 요약 내용이 클립보드에 복사된다 | 복사 후 다른 곳에 붙여 넣어 확인 |

참고: 요약 대기 시간은 성공 기준에 넣지 않는다. 무료 AI 모델을 쓰므로 시간이 들쭉날쭉하다(사용자 결정, 8절 참고).

## 3. 대상 사용자와 사용자 스토리

### 3.1 대상 사용자

- 주 사용자: 강의 자료나 논문 PDF를 읽고 공부해야 하는 대학생. 시험 기간이나 과제 마감 직전에 문서를 빨리 파악하고 싶다.
- 사용 환경: 별도 가입 없이 웹 주소에 접속해 바로 쓴다. (기기 범위는 열린 질문 Q9)

|----|---------------|-----------|

| U2 | 대학생으로서, 영어 논문을 올려도 한국어 요약을 받고 싶다. 그래야 읽기 전에 내용을 이해할 수 있다. | F3, F4 |

### 4.1 요약 길이 단계 (추천안, 확인 필요)

사용자는 "요약 길이를 고를 수 있어야 한다"까지만 정했다. 단계 수와 이름, 기본값은 PM의 추천안이다.

| 단계 이름 (추천안) | 핵심 내용 개수 | 용도 |
|--------------------|----------------|------|
| 짧게 | 3개 | 시간이 없을 때, 문서가 필요한지 훑어볼 때 |
| 보통 (기본값, 추천안) | 4개 | 일반적인 파악 |
| 자세히 | 5개 | 시험 공부, 과제 준비 |

- 핵심 내용 개수는 사용자가 정한 "3~5개" 범위 안에서 길이 단계에 대응시킨 것이다.
- 한 줄 요약은 모든 단계에서 항상 한 줄이다.
- 정의·용어·공식을 몇 개까지 보여 줄지는 단계별로 달라질 수 있으나 구체 개수는 열린 질문 Q2다.
- 단계 수(3단계가 적절한지), 이름, 기본값은 사용자 확인 후 확정한다.

### 5.2 범위 밖 항목

사용자가 이번에 하지 않기로 정한 것이다. 요청이 오더라도 이번 개발 범위에 넣지 않는다.

- 회원가입·로그인: 계정 없이 쓴다. 따라서 이전 요약 기록 보기 같은 계정 기반 기능도 이번에는 없다.
- 문서에 질문하기: 요약 결과만 제공하고 대화형 질의응답은 제공하지 않는다.
- 스캔 PDF 글자 인식(OCR): 글자가 들어 있지 않은 PDF는 요약하지 않고 오류로 안내한다.
- 여러 PDF 한꺼번에 요약: 한 번에 PDF 한 개만 처리한다.

## 6. 요약 화면 구성

요약 결과 화면에는 사용자가 정한 세 가지를 담는다. (위에서 아래 순서는 추천안이며 화면 설계에서 확정)

1. 한 줄 요약: 문서 전체를 한 문장으로. 화면 맨 위.
2. 핵심 내용 3~5개: 번호나 글머리표로 나열. 개수는 선택한 요약 길이에 따른다(4.1 추천안).
3. 중요한 정의·용어·공식: "용어 - 설명" 형태의 목록. 공식은 원문 표기를 유지하되 설명은 한국어로 쓴다. 공식 표기 방식(글자로 표시할지 등)은 열린 질문 Q7이다.

함께 놓는 화면 요소:

- 요약 복사 단추(F5): 복사 대상 범위(세 영역 모두인지)는 추천안으로 "화면에 보이는 요약 전체", 확인 필요.
- 요약에 사용한 파일 이름과 선택한 길이 표시(추천안, 확인 필요).
- 새 요약 시작 단추(F9, 있으면 좋음).

처리 중 화면: "요약 중" 진행 표시(F7). 오류 화면: 7절 안내 문구.

## 7. 오류 상황 목록과 안내 원칙

### 7.1 안내 원칙

- 이유를 알려 준다: "오류가 발생했습니다"처럼 막연한 문구가 아니라 무엇이 문제인지 말한다.
- 다음 행동을 알려 준다: 사용자가 무엇을 하면 되는지 한 문장으로 안내한다. 예: "4MB 이하 파일을 올려 주세요."
- 사용자 탓으로 느끼지 않게, 쉽고 짧은 한국어로 쓴다.
- 오류가 나도 다시 시도할 수 있게 업로드 화면으로 쉽게 돌아갈 수 있어야 한다.
- 내부 오류 내용(기술 용어, 서버 메시지, 비밀 값)은 사용자 화면에 노출하지 않는다.

### 7.2 오류 상황 목록

문구는 예시이며 최종 문구는 화면 설계에서 정한다.

| ID | 상황 | 분류 | 안내 예시 (추천안) |
|----|------|------|--------------------|
| E1 | PDF가 아닌 파일을 올림 | 필수 (사용자 결정) | "PDF 파일만 올릴 수 있어요. PDF로 저장한 뒤 다시 올려 주세요." |
| E2 | 파일이 4MB를 넘음 | 필수 (사용자 결정) | "파일이 너무 커요. 4MB 이하의 PDF를 올려 주세요." |
| E3 | 글자가 없는 PDF (스캔·이미지 PDF 등) | 필수 (사용자 결정) | "이 PDF에서는 글자를 읽을 수 없어요. 글자가 들어 있는 PDF를 올려 주세요. (스캔한 문서의 글자 인식은 아직 지원하지 않아요.)" |
| E4 | PDF가 손상됨 또는 열 수 없음 | 필수 (PM 추가, 확인 필요) | "파일을 열 수 없어요. 다른 PDF로 다시 시도해 주세요." |
| E5 | 비밀번호가 걸린 PDF | PM 추가, 확인 필요 | "비밀번호가 걸린 PDF는 요약할 수 없어요. 비밀번호를 푼 파일을 올려 주세요." |
| E6 | 파일을 고르지 않고 요약 시작 | PM 추가, 확인 필요 | "먼저 PDF를 골라 주세요." |
| E7 | AI 요약 서비스 오류·한도 초과·응답 시간 초과 | PM 추가, 확인 필요 | "지금은 요약을 만들지 못했어요. 잠시 뒤 다시 시도해 주세요." |
| E8 | 글자는 있지만 문서가 너무 길어 전부 처리하지 못함 | 사용자 결정(2026-11-26, Q6) | 오류가 아니라 앞부분만 요약하고 결과 화면에 "문서가 길어 앞부분만 요약했어요"라고 표시 |

사용자가 정한 오류 안내 범위는 "PDF가 아님, 너무 큼, 글자가 없는 PDF 등"이다. E1~E3은 확정이고 E4~E8은 "등"에 해당하는 PM 추가안이다.

## 8. 개인정보·저작권 고려

대학생이 올리는 강의 자료와 논문에는 저작권이 있는 문서가 많고, 개인정보(이름, 학번 등)가 들어 있을 수 있다. 아래 사항은 설계 단계 전에 정해야 하며 대부분 열린 질문이다.

- 올린 PDF를 서버에 저장하는가: 열린 질문 Q3. 저장하지 않고 요약 후 바로 버리는 방식이 개인정보·저작권 부담이 적다는 점을 설계 시 참고. 저장 여부는 확정하지 않는다.
- 요약 결과를 저장하는가: 열린 질문 Q3에 함께 포함. 로그인이 없으므로 저장하면 접근 제어 문제가 생긴다.
- PDF 내용이 외부 AI 서비스로 전달된다: 사용자에게 고지해야 하는가는 열린 질문 Q4.
- 무료 AI 모델이 입력 내용을 학습에 쓸 수 있는가: 설계 단계에서 모델 선택 시 확인할 사항, 열린 질문 Q5에 포함.
- 저작권: 사용자가 올린 자료의 요약을 개인 학습 용도로 제공한다. 요약 결과를 공유·재배포하지 않도록 안내 문구를 둘지는 열린 질문 Q4.
- 비밀 값(AI 서비스 접근 키 등)은 `.env`에 두고 저장소에 올리지 않는다. 문서와 화면, 로그에 값을 쓰지 않으며 설계 시 필요한 환경 변수는 이름만 `.env.example`로 안내한다.
