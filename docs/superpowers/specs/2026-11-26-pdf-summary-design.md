# 설계: PDF 요약 웹 앱

- 기준 문서: `docs/prd.md` (PRD v0.1, 2026-11-26). 이 설계는 PRD를 근거로 하며, PRD와 달라진 점은 7절에 모았다.
- 표기: **[사용자]** 사용자가 정함, **[PRD]** PRD에 정해짐, **[내 판단]** 설계자가 정함(사용자가 "빠르게 설계" 선택, 2026-11-26), **[빌더]** 구현하는 사람이 정해도 됨.

## 1. 의도와 이유

대학생이 강의 자료나 논문 PDF를 올려 핵심을 빨리 파악하고 시험 공부·과제 준비에 쓴다 **[PRD D1]**. 영어 논문도 한국어로 읽고 싶고, 시험에 나올 정의·용어·공식을 한곳에 모으고 싶다. 그래서 결과는 "읽고 바로 노트로 옮길 수 있는 한국어 요약"이어야 한다.

## 2. 목표, 비목표, 실패 조건

**목표**
- PDF 하나를 끌어다 놓거나 골라 올리면 한국어로 한 줄 요약, 핵심 내용 3~5개, 정의·용어·공식이 나온다 **[PRD F1~F4]**.
- 요약 길이를 고르고, 결과를 한 번에 복사한다 **[PRD F2, F5]**.
- 실패하면 이유와 다음 행동을 알려 준다 **[PRD F6]**.
- Vercel 배포 주소에서 같은 흐름이 동작한다 **[PRD F8]**.

**비목표 (이번에 안 함)** **[PRD D5]**: 회원가입·로그인, 문서에 질문하기, 스캔 PDF 글자 인식(OCR), 여러 PDF 한꺼번에, 결과 파일 내려받기(나중에), 요약 기록.

**실패 조건(동작해도 실패로 봄)**
- 영어 PDF의 요약이 영어로 나온다.
- 오류가 나면 "오류가 발생했습니다"처럼 이유 없이 끝난다.
- 올린 PDF나 요약이 서버 어딘가에 남는다.
- OpenRouter 키가 브라우저로 내려간다.

## 3. 제약

- **PDF 크기 4MB까지** **[사용자]**. Vercel 함수가 받는 요청 본문 한도(약 4.5MB) 안이다. 쪽수 제한은 두지 않는다 **[내 판단]**.
- **AI 모델:** OpenRouter의 `nvidia/nemotron-3-ultra-550b-a55b:free`를 먼저, 응답이 없거나 오류면 `nvidia/nemotron-3.5-super-vl:free`로 한 번 넘어간다 **[사용자]**. 키는 환경 변수 `OPENROUTER_API_KEY`, 서버에서만 읽는다 **[사용자]**.
- **무료 모델의 데이터 정책:** OpenRouter 무료 모델은 제공사가 입력을 기록하거나 학습에 쓸 수 있다. 이 조건으로 두 모델을 쓰고 업로드 화면 고지에 알린다 **[사용자, 2026-11-26, PRD Q5]**. 같은 키로 두 모델을 이미 호출해 본 적이 있어(공감 다이어리 앱) 계정의 무료 모델 허용 설정은 켜져 있다.
- **모델을 쓸 수 없게 되면:** 구현·배포 중 두 모델 중 하나가 OpenRouter 목록에서 없어지거나 무료가 아니게 되면, 다른 모델로 바꾸지 말고 **멈추고 사용자에게 묻는다** **[사용자, 2026-11-26]**. 첫 구현 태스크에서 공개 모델 목록으로 두 ID가 있는지 먼저 확인한다.
- **무료 모델 한도:** 계정당 하루 약 50회. "길이 바꿔 다시 요약"도 1회로 센다. 시험에서 실제 호출을 아끼고 나머지는 응답을 흉내 낸 시험으로 한다 **[내 판단]**.
- **Next.js**로 만들고 GitHub `summary4pdf-ch7`(이미 공개 저장소로 있음)에 올려 **Vercel**에 배포 **[사용자]**. 요금제 Hobby(무료)를 가정 **[내 판단]**. 함수 실행 시간 한도는 구현 때 Vercel 문서로 확인한다.
- `.env`는 열거나 읽지 않는다. 필요한 변수는 `.env.example`에 이름만 적는다(CLAUDE.md).

## 4. 접근 방식 (Approaches)

| 방식 | 내용 | 장단점 |
|---|---|---|
| **A. Next.js 한 앱, 서버에서 추출·요약 (선택)** | 화면에서 PDF를 `/api/summarize`로 보내고, 서버가 검사 → 글자 추출 → OpenRouter 요약 → JSON 응답 | 구조가 단순하고 키가 서버에만 있음. 4MB 제한이 Vercel 본문 한도 안이라 그대로 가능. 사용자의 역할 분담(백엔드가 업로드·추출)과 맞음 |
| B. 브라우저에서 글자 추출, 서버엔 글자만 | pdf.js로 브라우저에서 추출 후 글자만 전송 | 큰 파일도 가능하지만 화면 코드가 무거워지고, "백엔드가 추출" 분담과 어긋남 |
| C. 별도 백엔드 서버 | Next.js 화면 + 따로 둔 API 서버 | 배포 대상이 둘이 되어 이번 범위에 과함 |

A를 고른 이유: 사용자가 정한 역할 분담과 Vercel 배포에 가장 잘 맞고, 4MB 제한 덕분에 B가 필요 없다 **[내 판단]**.

## 5. 정해진 설계

### 5.1 화면 흐름 (한 페이지)

```
[업로드]  ── PDF 끌어다 놓기 / 파일 고르기 ──  요약 길이: (짧게)(●보통)(자세히)  [요약하기]
   │        안내 한 줄: "올린 PDF는 이 앱에 저장하지 않아요. 내용은 요약을 위해 외부 무료 AI로 전달되고, 그곳에서 기록·학습에 쓰일 수 있어요."
   ▼
[처리 중]  "요약하는 중이에요 (12초)" — 지난 시간만 표시, 취소 없음
           (요청이 한 번이라 서버의 단계를 알 수 없으므로 단계별 표시는 하지 않음 [내 판단, 설계 검토])
   ▼
[결과]    파일 이름 · 선택한 길이
          ① 한 줄 요약
          ② 핵심 내용 3~5개 (번호 목록)
          ③ 정의·용어·공식 ("용어 — 설명", 공식은 고정폭 글꼴로 원문 그대로)
          (앞부분만 요약했으면) "문서가 길어 앞부분만 요약했어요"
          [전체 복사] [길이 바꿔 다시 요약] [새 PDF 요약]
   ▼ (실패 시)
[오류]    이유 한 문장 + 다음 행동 한 문장 + [다시 시도]
```

- 끌어다 놓기와 파일 고르기 단추를 **둘 다** 둔다. 끌어다 놓기는 **필수** **[사용자, 2026-11-26, PRD F10 변경]**.
- 화면 순서: 한 줄 요약 → 핵심 내용 → 정의·용어·공식 **[PRD 추천안 채택, 내 판단]**.
- "길이 바꿔 다시 요약"(PRD F11)은 브라우저가 고른 파일을 그대로 들고 있다가 다시 보낸다. 서버에 저장하지 않으므로 이 방식이 유일하다 **[내 판단]**.
- "새 PDF 요약"(PRD F9)은 업로드 화면으로 돌아간다 **[내 판단]**.
- 휴대폰 화면에서도 깨지지 않게 반응형으로 만든다(완료 기준은 아님) **[내 판단, PRD Q9]**.
- 모든 글은 한국어.

### 5.2 요약 길이 **[PRD 추천안 채택, 내 판단, PRD Q1·Q2]**

| 길이 | 핵심 내용 | 정의·용어·공식 최대 |
|---|---|---|
| 짧게 | 3개 | 3개 |
| 보통(기본) | 4개 | 5개 |
| 자세히 | 5개 | 8개 |

정의·용어·공식은 문서에 없으면 0개여도 된다.

### 5.3 처리 흐름 (`POST /api/summarize`)

1. `multipart/form-data`로 파일 하나와 길이(`short`/`medium`/`long`)를 받는다.
2. 검사: 파일 없음 → E6, 4MB 초과 → E2, PDF가 아님(파일 머리 `%PDF-` 확인) → E1.
3. 글자 추출. 비밀번호 PDF → E5, 열 수 없음 → E4, 추출된 글자가 거의 없음 → E3.
4. **긴 문서:** 추출한 글자를 통째로 쓰되, 정한 글자 수 한도를 넘으면 앞부분만 쓰고 `truncated: true` **[사용자, 2026-11-26: 교수 설계와 같게, PRD Q6·E8 결정]**. 한도 값은 **[빌더]**(두 모델의 문맥 크기와 Vercel 실행 시간 안에 끝나는 값으로).
5. OpenRouter 1순위 호출 → 시간 초과·오류·빈 응답·형식 오류면 2순위 한 번. 둘 다 실패하면 E7.
6. 모델 응답을 검사하고 아래 형식으로 돌려준다. 형식 오류(다음 모델로 넘어감)는 JSON이 아니거나, 한 줄 요약이 없거나, 핵심 내용이 하나도 없을 때만이다. 핵심 내용 개수가 길이별 숫자와 달라도 1개 이상이면 받아들이고, 넘치면 길이별 개수로 잘라 쓴다. 정의·용어·공식도 넘치면 잘라 쓴다 **[내 판단, 설계 검토: 무료 모델은 개수를 자주 틀림]**.
7. 파일과 글자는 메모리에서만 다루고 어디에도 저장하지 않는다 **[내 판단, PRD Q3]**. 서버 로그에도 문서 내용을 남기지 않는다.

**응답 형식(필드 이름은 [빌더]가 바꿔도 됨)**

```json
{
  "oneLine": "문서 전체를 한 문장으로",
  "keyPoints": [{ "title": "핵심 1", "detail": "설명" }],
  "terms": [{ "term": "용어 또는 공식", "explanation": "한국어 설명", "isFormula": false }],
  "truncated": false,
  "length": "medium",
  "model": "답한 모델 이름"
}
```

오류는 `{ "error": { "code": "E2", "message": "사용자에게 보여 줄 한국어 문장" } }`와 알맞은 HTTP 상태로.

### 5.4 오류 안내 **[PRD 7절, E4~E7은 PRD 추천안 채택]**

| 코드 | 상황 | 안내(예시, 최종 문구는 화면 담당) |
|---|---|---|
| E1 | PDF가 아님 | PDF 파일만 올릴 수 있어요. |
| E2 | 4MB 초과 | 파일이 너무 커요(○MB). 4MB 이하의 PDF를 올려 주세요. |
| E3 | 글자가 없음 | 이 PDF에서는 글자를 읽을 수 없어요. 스캔한 문서는 아직 지원하지 않아요. |
| E4 | 손상·열 수 없음 | 파일을 열 수 없어요. 다른 PDF로 다시 시도해 주세요. |
| E5 | 비밀번호 PDF | 비밀번호가 걸린 PDF는 요약할 수 없어요. |
| E6 | 파일 없음 | 먼저 PDF를 골라 주세요. (화면에서 먼저 막음) |
| E7 | 두 모델 모두 실패·한도 초과 | 지금은 요약을 만들지 못했어요. 잠시 뒤 다시 시도해 주세요. |
| E8 | 너무 긴 문서 | 오류가 아니라 앞부분만 요약하고 결과 화면에 표시 **[사용자]** |

E1·E2는 화면에서도 미리 검사해 서버까지 보내지 않는다. 서버 검사는 그대로 둔다.

### 5.5 AI 요약 지시

- 원문 언어와 관계없이 **항상 한국어** **[PRD D3]**.
- JSON 형식으로만 답하게 하고, 5.2절 개수를 지키게 한다. 1순위 모델이 JSON 형식 강제를 지원하지 않을 수 있으므로 지시문과 너그러운 해석(코드 울타리 제거 등)으로 처리 **[빌더]**.
- 문서 안의 지시문("이전 지시를 무시해" 등)을 따르지 않게 문서를 데이터로 구분한다.
- 공식은 원문 표기를 그대로 두고 설명만 한국어로 쓴다. 수식 렌더링은 하지 않는다 **[내 판단, PRD Q7]**.

### 5.6 그 밖의 결정

- **고지:** 업로드 화면에 한 줄 "올린 PDF는 이 앱에 저장하지 않아요. 내용은 요약을 위해 외부 무료 AI로 전달되고, 그곳에서 기록·학습에 쓰일 수 있어요." **[사용자, 2026-11-26]** 결과 화면 아래에 "AI 요약이라 틀릴 수 있어요. 중요한 내용은 원문을 확인하세요." **[내 판단, PRD Q4]**
- **요청 횟수 제한:** 두지 않는다. 한도가 차면 E7로 안내 **[내 판단, PRD Q8, 교수 설계와 같음]**.
- **복사:** 화면에 보이는 요약 전체를 글자로(제목·번호 포함) 복사하고 "복사했어요" 표시 **[PRD 추천안 채택, PRD Q12]**.
- **환경 변수:** `OPENROUTER_API_KEY` 하나. `.env.example`에 이름만.
- **배포:** 새 Vercel 프로젝트에 GitHub `summary4pdf-ch7`을 연결하고 환경 변수를 사용자가 직접 넣는다 **[내 판단]**.

## 8. 시험과 완료 기준

PRD 성공 기준 S1~S5를 그대로 쓴다. 시험용 PDF: 한국어 강의 자료, 영어 논문, 공식이 있는 문서, 아주 긴 문서, 스캔 PDF, 비밀번호 PDF, 손상 PDF, PDF가 아닌 파일, 4MB 초과 파일 **[빌더가 준비]**. 실제 모델 호출 시험은 하루 한도를 고려해 꼭 필요한 만큼만.

## 9. 빌더에게 남긴 것

Next.js 세부 버전과 폴더 구조, PDF 글자 추출 라이브러리(서버리스에서 도는 것), 모델별 제한 시간과 전체 시간 예산(`maxDuration`), 긴 문서 글자 수 한도, 지시문 문구, 응답 필드 이름, "글자가 거의 없음" 판단 기준, 시각 디자인 세부, 시험 도구.
